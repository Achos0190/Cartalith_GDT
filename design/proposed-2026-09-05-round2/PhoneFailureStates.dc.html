EVERY VALUE DRAWN, AND WHERE IT COMES FROM
LAST STAGE STARTED real — generation_stage(index, name, total), held in app.gd's _mid_running_stage and currently discarded on failure
STAGES RESOLVED real — the stage index, against STAGE_COUNT = 10 in progress.rs
RAN FOR real — last_generate_ms, written before the ok branch, so a failure still has it
SEED · RESOLUTION real, and shell-side — the request dictionary the sheet built. Labelled “asked for”, because the engine's own readback is not trustworthy after a failed run
88.0 MiB NEEDED real — 2048² × 21 B + 4 MiB, from SAVE_BYTES_PER_CELL and SAVE_PROJECT_LAYER_ALLOWANCE
148 MB ATLAS CACHE real — atlas_status() reports chunks and bytes; atlas_clear() returns what it freed
ENGINE REASON absent — drawn as a dash. generation_finished carries one boolean; the save's engine-side reason is pushed as a warning and never returned to the caller
FREE ON THIS VOLUME absent on Android — drawn as a dash. volume_free_bytes() is #[cfg(windows)]; everything else returns −1, and the Rust doc says to draw it unavailable rather than as “plenty of room”
THREE RULES THESE PANELS FOLLOW
1 · Say what survived, first. Both failures leave something intact and both intacts are provable — a failed generate returns before it writes anything, and a failed save cannot have damaged the file already there. Neither is reassurance; both are guarantees.

2 · Never dress a missing cause as a cause. “Unknown error” and “see console” are both worse than a dash. The dash with one sentence under it is the honest form, and the sentence says whether the answer is unavailable or simply not asked for.

3 · Every action changes something real. Retry at half resolution moves a parameter that exists. Clear atlas cache frees bytes something measures. Save as… picks a different volume. No button here merely dismisses the panel while leaving the user where they were.
NOT SETTLED HERE
Frame 2 is unreachable on Android until a free-space query exists there — a one-line manifest change by the Rust doc's own account, but a change. Drawn anyway, because it is right on desktop today and is the state the handset should get.
Whether a failed generate should offer RETRY AT 1024² unconditionally, or only above some resolution, is an owner call: the engine reports no memory ceiling to test against.
