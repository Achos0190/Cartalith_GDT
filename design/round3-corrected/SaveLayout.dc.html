_prompt_save_layout() is a complete modal: a name well pre-filled “Layout N”, select-on-focus, a note stating exactly what is stored, replace-not-duplicate, a status hint on save, and phone presentation through phone_window. _prompt_forget_layout() mirrors it with an OptionButton, because forgetting is destructive and the valid answers are finite. SMALLER, AND OPTIONAL
A live collision warning. Typing an existing name replaces it — the note says so, and the OK button still reads Save. A one-line warning under the well when layouts().has(name), and the button reading Replace, would say it at the moment it matters. Not a defect; the behaviour is already documented and correct.
Dock widths stay uncaptured, and stay dashed. Neither this design nor the last resolved whether a layout should carry them. Drawn as an explicit “not captured” row rather than omitted, so the answer is visible instead of assumed.
