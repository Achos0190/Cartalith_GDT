B3 · THE ONE CHOICE
Keep the centred dialog, or move to a status-bar locator?
The earlier canvas proposed QGIS's locator: a 250×17 field living in the status bar, no modal at all.
Recommendation: keep the dialog. The four additions above are worth having on their own and do not depend on where the field lives. Moving it is a separate change that touches the status bar's own layout, and the dialog is not the thing that is wrong today.
If it does move, the honest reason is that AcceptDialog is one of the stock dialogs round 1 was reducing — 11 sites down to 5. That is an argument for the modal pattern, not necessarily for the status bar.
DASHED, WITH THE CODE'S OWN REASON
l · landmarks. icon_list() carries family / slot / set / scale — four closed vocabularies and no identifying name — so a row reading “pine / forest” is not a place anyone typed a name to find. place_search.gd declines them in writing. A scope that always returns nothing is worse than an absent one; it ships when a placed landmark has one identifying name.
Ranking is not a proposal. Case-insensitive substring, deliberately not fuzzy, three bands each alphabetical, first band a row qualifies for. That is what search() already returns — the bands above only draw a grouping the order already has.
Row handles go stale on add/remove. Index-based for settlements, labels, roads and sea routes; the faction id itself for factions. Same as every other index handle in the shell, and the reason build() is wholesale on every open.
