The first round-3 canvas drew these three against an Exists today column that did not hold. Each claim below was re-checked against origin/main 0732cfc — the exact commit that canvas cites — and against the working branch, which is 43 commits ahead of it.
THREE PREMISES THAT DID NOT HOLD
Rail expansion. Declined the node-tree model because “the spec never enumerates the sub-nodes, so there is nothing to build”. RAIL_NODES enumerates thirteen rows — three headers and ten navigable nodes — and _build_rail_expansion() already builds them into the very column the design targets. Drawing labels-and-subtitles instead would have replaced ten working navigation targets with three inert lines.
Find on map. “The menu row exists and is disabled”, accelerator “no”. It is _live with Ctrl+F bound, and open_find_on_map() opens a working dialog on desktop and an overlay on phone.
Save layout as… Modal “no”. _prompt_save_layout() is a complete modal — name well, seeded default name, a note stating exactly what is stored, replace-not-duplicate, a status hint and phone presentation. Its “known defect this design assumes fixed” was fixed on 2026-09-01.
So these three artboards draw what is on screen today, then the gap that is actually left. Nothing here proposes replacing working behaviour. Every dashed field carries the code's own reason.
